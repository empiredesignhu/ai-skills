# Goal
Turn visual and interaction standards into reusable tokens, components, and implementation rules that scale across a product.

# Instructions
1. Inspect the current component inventory, repeated patterns, and inconsistencies across the codebase.
2. Define or refine shared tokens for color, type, spacing, radius, elevation, and motion before widespread UI changes.
3. Group repeated UI into reusable primitives and composed components with stable naming.
4. Encode variants, states, and theming rules consistently instead of per-screen exceptions.
5. Verify that migrated UI stays visually aligned while reducing duplication.

# Input
A request to implement or improve a design system, extract tokens, standardize components, or make an interface more internally consistent.

# Output
Design tokens, shared components, theming rules, migration updates, and brief notes about adoption strategy when needed.

# Best Practices
- Keep token names semantic enough to survive redesigns.
- Separate foundational primitives from higher-level product components.
- Standardize interaction states, spacing rhythm, and typography hierarchy across the system.
- Avoid one-off overrides that quietly reintroduce inconsistency.
