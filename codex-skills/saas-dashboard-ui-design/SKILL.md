# Goal
Create dashboards that make product data, workflow status, and next actions legible without overwhelming the user.

# Instructions
1. Identify the primary user role, top tasks, and decisions the dashboard must support.
2. Prioritize information hierarchy before visual styling: overview metrics, alerts, actions, filters, and detail areas.
3. Use layout patterns that support scanning, comparison, and drill-down without crowding the screen.
4. Design states for empty data, loading, errors, and edge cases alongside the happy path.
5. Refine density, contrast, and interaction affordances so the dashboard remains usable over long sessions.

# Input
A request to design or build a SaaS dashboard, analytics view, admin panel, back office screen, or product workspace.

# Output
Dashboard layouts, components, frontend implementation, and structural decisions that improve clarity and actionability.

# Best Practices
- Keep the user's next action obvious even on dense screens.
- Use consistent cards, tables, filters, and navigation patterns across views.
- Avoid decorative complexity that competes with data legibility.
- Support responsive behavior for laptop and tablet use, not only wide desktop monitors.
